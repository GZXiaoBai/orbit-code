## Runtime Matrix

| 区域 | 状态 | 当前事实 | 下一步 |
| --- | --- | --- | --- |
| Codex sidecar lifecycle | `partial` | Rust Codex command now prepares a pinned sidecar, starts one persistent `codex app-server --listen stdio://`, generates no-secret temporary config, routes JSON-RPC responses through pending channels, maps app-server notifications to fixed Tauri events, and caches `Orbit threadId -> Codex threadId` for the sidecar lifetime. The former monolithic `src-tauri/src/commands/codex.rs` is now a 12-line façade with physical shards under `src-tauri/src/commands/codex/` for types/state, JSON-RPC, Responses bridge, direct Plan, app-server lifecycle, notification mapping, turn commands, response translation, and tests. Build turns now use Codex `untrusted` approval policy so command execution goes through approval requests. Independent live smoke has proven real app-server initialize/thread/start, approval request/response, terminal output, temp file edit, usage, final assistant summary, and turn completion with DeepSeek traffic. Permissions approval requests now map to explicit Orbit approval metadata instead of a generic fallback. App-server failure cleanup now clears stdin/child/thread cache/active context and releases every pending response, so sibling requests do not remain stuck after one timeout or disconnected channel. Final app-server errors now use a stable per-turn item id, allowing frontend upsert to keep one terminal error card instead of appending repeated red cards. Early app-server errors/retries now retain the Orbit turn id until Codex returns an app turn id, so Build failures before `turn/started` stay attached to the active UI turn. | Add stronger recovery tests for sidecar crash/restart while a turn is active, then run real desktop Build smoke. |
| Orbit provider bridge | `partial` | Bridge 绑定 `127.0.0.1:0` 并提供基础 HTTP loop：`GET /v1/models`、`POST /v1/responses`。DeepSeek `/v1/responses` 从 vault 内存读取 key，完成 history sanitization、DeepSeek chat completion translation、SSE reasoning/content/tool/usage frames。Rust bridge now has pure parser coverage for streamed DeepSeek reasoning/content/tool_call/usage aggregation. OpenRouter、Qwen/DashScope、SiliconFlow、Kimi、Groq、自定义 OpenAI-compatible 均有 catalog 和 blocked reason。Independent Node live bridge has proven the same DeepSeek credential can drive real Codex app-server approval, command output, usage, final summary, and file edit in a temp workspace. Packaged desktop Build smoke now exists and can run live via `ORBIT_DESKTOP_BUILD_LIVE=1`; macOS local run remains blocked by WebDriver limits. Rust DB/vault and live smoke scripts now support `ORBIT_APP_DATA_DIR`, so credentialed Ubuntu CI can run against an isolated encrypted vault. | Trigger the `desktop-build-live` workflow in the protected `orbit-live-smoke` environment and promote the latest report from wired to verified. |
| Frontend runtime | `partial` | `useWorkspace.ts` remains a workbench facade and no longer imports old runner/tool loop. `useCodexSession` consumes `AgentRuntimePort`, event notifications, sidecar version info, restart result, and runtime settings model. Build is the only Codex app-server route; if the sidecar is not already ready, the effective workspace Build gate now becomes blocked before submission, so the RunControl/Settings state and the submitted turn agree on the same sidecar-not-ready reason instead of entering a half-running turn. Composer and `useCodexSession.submit()` now derive submit lock from runtime/active-turn state: running turns block duplicate submissions, failed/interrupted/completed turns restore submission, and the draft remains editable. | Add broader state-machine tests for streaming/retry/approval/reload recovery. |
