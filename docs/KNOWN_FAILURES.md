# Known Failures

| Area | Status | Detail |
| --- | --- | --- |
| Codex app-server turn lifecycle | `partial` | `codex_turn_start` now returns a running turn after submitting `turn/start` to a persistent app-server. `Orbit threadId -> Codex threadId` is cached for the lifetime of the sidecar process. `npm run smoke:deepseek:live-app-server` has proven initialize, thread/start, approval request/response, terminal output, usage, final assistant summary, turn completion, and temp workspace file write with real DeepSeek traffic. Remaining risk is long-turn recovery and desktop UI Build parity. |
| Codex JSON-RPC routing | `partial` | Fake app-server tests cover initialize, request/response routing, approval submit, interrupt, retry/error mapping, crash cleanup, timeout cleanup that releases all pending responses instead of leaving sibling requests stuck, stable per-turn app-server error item ids, and early app-server error/retry attachment to the Orbit turn before Codex returns an app turn id. The independent live app-server smoke now observes command approval requests and auto-submits acceptance. Remaining live gaps are question/tool-result/interrupt and crash recovery with real provider traffic. |
| Responses bridge | `partial` | Loopback `/v1/models` and `/v1/responses` exist for DeepSeek, including history sanitization and SSE frame translation. Other providers remain discovery-only with Build blocked until their adapters are verified. |
| Plan/ordinary chat runtime | `stabilized first pass` | Plan/ordinary chat no longer initializes or restarts Codex app-server. The frontend route is `direct-deepseek-plan`; Rust handles it through direct provider streaming and emits Codex item deltas. Rust now has a command-layer regression proving Plan routes to direct provider even without explicit `runtimeMode`. `npm run smoke:plan` combines the UI route fixture (`smoke:plan-route`) and live DeepSeek SSE check (`smoke:plan-live`) into one stability gate. Packaged-window automation now has `npm run smoke:desktop-plan`: macOS remains blocked because WKWebView has no WebDriver, while Linux/Windows can launch the real Tauri binary and optionally run live Plan submit with `ORBIT_DESKTOP_PLAN_LIVE=1`. |
| DeepSeek smoke | `verified independent live driver` | `npm run smoke:plan-live` verifies direct Plan/chat DeepSeek SSE without exposing the key. `npm run smoke:deepseek` runs the prepared sidecar + app-server routing contract smoke. `npm run smoke:deepseek:live-readiness` verifies the trusted-device vault, DeepSeek credential, prepared sidecar, and DeepSeek `/v1/models` reachability without exposing the key. `npm run smoke:deepseek:live-app-server` starts the real prepared sidecar and a local Responses bridge, then verifies DeepSeek live streaming, approval request/response, terminal output, temp workspace file edit, usage, final assistant summary, and turn completion. |
| E2E | `verified fixture path` | Playwright fixtures use Codex thread/turn/item shapes. Remaining risk is drift between fixture items and real Codex app-server notifications. |
| Legacy sessions | `verified first pass` | Runtime does not restore old snapshots; UI shows legacy unsupported/delete behavior. Last-thread deletion and empty-thread UX still need continued regression coverage. |
