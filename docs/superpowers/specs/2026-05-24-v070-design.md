# v0.7.0 — Tree-sitter AST + CI + useWorkspace Split — Design Spec

## Goal

三线并行的架构升级：tree-sitter AST 解析（代码理解质变）、E2E CI 集成（自动化测试）、useWorkspace 拆分（架构清洁）。

## P0: Tree-sitter AST Parser

### Architecture
- New: `src-tauri/src/ast_parser.rs` — tree-sitter wrapper with fallback
- Modify: `src-tauri/src/code_graph.rs` — use AST parser as primary path
- Modify: `src-tauri/src/embedding.rs` — AST-based chunk boundaries
- New deps: tree-sitter, tree-sitter-typescript, tree-sitter-python, tree-sitter-rust

### Strategy
Primary: tree-sitter AST parsing → Fallback: existing string matching (parse_typescript_fallback etc.)

### New Node kinds
"method", "arrow_fn", "constructor", "property", "call"

### New Edge kinds
"calls", "extends", "implements", "contains"

### Key Deliverable
CodeGraph with call graph, inheritance graph, and precise symbol boundaries.

## P1: E2E CI Integration

### Files
- New: `.github/workflows/ci.yml` — 3 jobs: frontend (vitest+build), e2e (playwright), rust (cargo test)
- Modify: `package.json` — add test:e2e, test:all scripts
- Install: `@playwright/test` devDependency

## P2: useWorkspace Split

### Architecture
```
useWorkspace.ts (~700 lines) coordinator
  ├── useSession.ts (~250 lines) — session, plan, config, keychain
  └── useFileSystem.ts (~200 lines) — files, shell, patches
```

### Strategy
Extract useFileSystem first (most independent), then useSession (existing scaffold), then slim useWorkspace.
Agent collaboration flow stays in useWorkspace (too intertwined).
